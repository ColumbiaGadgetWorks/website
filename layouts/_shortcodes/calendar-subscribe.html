{{- /* "Add to your calendar" buttons and a copyable feed address. The feed is the site's own /api/calendar.ics (src/calendar.js), rebuilt from the events the page shows. The address the Worker reads may be a Google secret address, which is a credential and must never appear in a page, so it is never linked here. calendarPublicUrl, when set, points the buttons at a public Google calendar instead, which Google keeps more current than a feed it polls. */ -}} {{- $ics := site.Params.calendarPublicUrl | default ("/api/calendar.ics" | absURL) -}} {{- /* webcal:// is not a scheme Go's html/template treats as safe, so without safeURL the href is rewritten to #ZgotmplZ and the button goes nowhere. The value is our own configuration, never anything a visitor supplies. */ -}} {{- $webcal := replaceRE "^https?://" "webcal://" $ics -}} {{- /* Adding a public Google calendar by its calendar id subscribes to it live. Adding it by feed URL instead makes Google poll the .ics, which can lag most of a day. Only the /public/ form is matched, so a secret address put here by mistake is still never turned into a link. Any other feed is handed to Google as its webcal:// address. */ -}} {{- $gid := replaceRE `^https?://calendar\.google\.com/calendar/ical/([^/]+)/public/basic\.ics$` "$1" $ics -}} {{- $cid := cond (ne $gid $ics) $gid ($webcal | urlquery) -}} {{- /* The id out of the path is already percent-encoded, so the whole href is marked safe. Interpolating it normally makes Go re-encode the percent and Google then receives a calendar id that does not exist. */ -}} {{- $addGoogle := printf "https://calendar.google.com/calendar/render?cid=%s" $cid | safeURL -}}
